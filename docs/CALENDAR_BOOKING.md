# Local Telegram scheduling

`/book YYYY-MM-DD HH:MM MIN title` is the user's explicit authorization to create one event without a second prompt. Times use America/Chicago; valid durations are 5–240 minutes. `/block` optionally saves a proposal for `/confirm`; `/cancel` discards the proposal, not an event that may already exist. `/calendar` checks connectivity.

The local runtime remains Telegram's only getUpdates consumer. It sends outbound HTTPS requests to the Google Apps Script bridge; no inbound port, tunnel, or public local server is required. Install CalendarBridge.gs alongside the existing relay source, enable the advanced Calendar API v3 service in the default Apps Script project, keep KIKI_CALENDAR_ONLY=true, and deploy a Google-hosted Web app that executes as the Kiki account. A generated 256-bit CALENDAR_BRIDGE_KEY in private Script Properties authenticates HMAC-SHA256 request bodies. The matching key and /exec URL belong in the Windows user environment as KIKI_CALENDAR_BRIDGE_KEY and KIKI_CALENDAR_BRIDGE_URL, never in source or URLs.

Set WRITE_CALENDAR_ID to Kiki's calendar and READ_CALENDAR_IDS to all calendars whose busy events must block bookings, including the subscribed work calendar. Calendar reads require calendar.readonly; inserts additionally require calendar.events. Google authorization and web-app deployment approval are one-time setup steps, not confirmations for each appointment. Do not switch the relay back into Telegram polling mode.

SQLite stores request IDs and booking results before/after calls. Telegram update IDs produce stable request IDs, so replay after interruption does not create another event. Google event IDs are derived from those request IDs; lost HTTP responses can safely be retried with /confirm. Neither HTTP errors nor event data are printed in logs. Unsigned, tampered, and stale requests are rejected. Requests expire after 30 minutes and daylight-saving skipped/ambiguous times are rejected.

Before insertion, all configured calendars are re-read, pagination is followed, canceled/free events are ignored, and overlapping busy events block creation. Any inaccessible configured calendar blocks booking. External calendar subscriptions may refresh late; checks cannot detect an Outlook change Google has not synced. Conflict checking and insertion cannot be atomic with unrelated calendar editors. The script lock serializes Kiki's own writes. No guests are added and no invitation mail is sent automatically.

Validation: run `python -m unittest discover -s tests -p "test_*.py" -v` and `node --test tests/relay.test.cjs tests/calendar_bridge.test.cjs`. Live acceptance requires /calendar, a /book in a free future slot, one resulting Google event, conflict rejection, and visibility in the Outlook subscription. Until deployed and live-verified, scheduling remains unconfigured.
