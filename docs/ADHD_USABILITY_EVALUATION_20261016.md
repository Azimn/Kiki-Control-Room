# Kiki: ADHD and cognitive-accessibility usability evaluation

Date: October 16, 2026
Status: Expert cognitive walkthrough + source-level behavioral testing, NOT a recruited participant study or live browser performance audit.
Implementation: [PR #9](https://github.com/Azimn/Kiki-Control-Room/pull/9) based on PR #7; [AIRI proactive companion PR #10](https://github.com/Azimn/Kiki-Control-Room/pull/10) is separate.

## Product outcome

Kiki is successful when the owner does not need to (a) remember the task, (b) choose which task, (c) invent the starting step, (d) watch the clock, or (e) reconstruct the stopping point. Count executive operations transferred to Kiki, not accumulated buttons or chat messages. Kiki cannot legitimately replace the owner's judgment or authorize consequential external actions without appropriate approval.

## Research-to-design mapping

- CHADD adult-workplace guidance recommends external memory supports, short intervals, written steps, reminders and chunking long projects. Apply this through one visible next action and a persisted recovery marker: https://chadd.org/for-adults/succeeding-in-the-workplace/
- CHADD time blindness: visual timers, buffers, task segmentation and body doubling are practical strategies. Optional timer should never create punitive streaks or certify completion: https://chadd.org/adhd-news/adhd-news-adults/attention-time-unbound-managing-time-blindness-at-work/
- NICE NG87 describes personalized ADHD environmental modifications, short focus periods with movement breaks, reduced distraction and written follow-up. Apply opt-in focus controls and preserved next-step text: https://www.nice.org.uk/guidance/ng87/chapter/Recommendations
- W3C cognitive accessibility recommends clear control purpose and limiting interruptions. Apply hidden backlog by default, labeled controls and pause/no-repeat affordances: https://www.w3.org/WAI/WCAG2/supplemental/objectives/o5-user-focus/
- Goblin Tools: tiny task breakdown, specifically Magic ToDo; adapt narrow grounded playbooks, not autogenerated source-task content. https://www.goblin.tools/
- Tiimo: visual plan and flexible reentry. Adapt visible current step without requiring perfect compliance. https://www.tiimoapp.com/product
- Routinery: guide through the next action and support automatic transition; adapt step-by-step workflow. https://blog.routinery.app/timer-guide
- Amazing Marvin: suggested task and super-focus mode; adapt a selected task with a hidden backlog. https://help.amazingmarvin.com/amazing-marvin/i-have-adhd
- Focusmate: structured coworking and body doubling; adapt a conversational accompaniment goal, but do not claim an AI timer alone is social body doubling or clinically effective. https://www.focusmate.com/body-doubling/
- Cochrane adult ADHD CBT review reports low-quality short-term evidence for nonpharmacological treatment benefit. Design strategies are plausible supports, not proof this interface treats ADHD. https://www.cochrane.org/evidence/CD010840_cognitive-behavioural-therapy-attention-deficit-hyperactivity-disorder-adhd-adults

## Synthetic cognitive walkthroughs

A. **Unplanned start, two open tasks.** The user returns with no recollection of what to do. Prior reviewed interface exposed tasks with a 'Start focus timer' control and offered no specific step; a meaningful starting action required the user to select and plan. New flow chooses the oldest non-snoozed open task and renders the first concrete step. Owner action before start: one button, 'Start with this step.' The task suggestion is not presented as a verified urgency ranking.

B. **Interruption after progressing one step.** The user reports step completion, pauses, shuts the browser, and returns on a separate authenticated device. Required: same objective, next action, pause status and last reported outcome. Resume must be one explicit action, with no transcript rereading. Automated tests persist these fields through an in-memory database and independent API calls. Real device/browser restart remains untested.

C. **Decline and reentry.** The user does not want the suggested task now. 'Not now' makes an atomic paused session, retaining the exact step. It does not schedule nagging. Proactive AIRI logic already suppresses paused sessions. User can return without rebuilding the plan.

D. **Conflicting two-device edits.** A stale revision must fail, not silently erase an updated next action. Duplicate network retries must produce one operation receipt and the same state. Automated regression covers both.

E. **Institutional email candidate.** A synthesized title may yield an email-category first action, but no content or recipient is invented and no send occurs. The task stays open after a work block. A future full email demonstration must use synthetic data or an approved institutional environment.

F. **Distracting phone layout.** The actionable work card comes before portrait; other tasks are collapsed; actions use large touch targets. Reduced-motion CSS remains. Needs actual 320px/375px/768px visual review, zoom to 200%, keyboard-only navigation, screen reader names, contrast validation and a real device speech test.

G. **Local machine offline or stale snapshot.** The offer identifies source and staleness. The user can work with a previously synchronized commitment, but the app cannot imply live PC connection, updated task state or an actual completed action.

H. **No model renderer / low capability.** The Site must continue to call its message area a journal; no animated thinking state or claim of assistant reply. The AIRI local bridge may offer actual conversation separately if installed. Text-only work guidance remains possible without inference.

## Quantitative acceptance measures

Capture for each observed session: number of user decisions before useful activity; seconds from seeing Kiki's invitation to first action; number of times the user needs to remember or restate prior context; number of steps Kiki proposes independently; percentage of interruptions with exact-state recovery; prompts delivered during a pause/decline; and fraction of claimed completions backed by evidence.

Engineering targets, not empirical outcomes: one owner click to accept and one click to resume; zero context items that must be reconstructed after a successful shared-state recovery; zero unsolicited reminders while paused; zero auto-sent emails; zero claimed external actions without receipts; zero falsely live connection labels. Compare against the previous version in a counterbalanced real-user usability test before calling ADHD benefit established.

## Test evidence

The new Site automated suite checks grounded task offers, deterministic first steps, deadline nonfabrication, snooze exclusion, typed states, step progression, pause/deferral, persisted resume, stale-revision conflicts, replay idempotency, cross-owner isolation, and strict separation of work-block completion from task completion. The added workflow is `.github/workflows/executive-usability.yml`. The AIRI branch adds privacy- and quiet-hour-compatible proactive task-selection tests.

Tests cannot establish natural conversational quality, whether the owner feels supported instead of managed, voice interruption, browser rendering, WCAG conformance, or improvement in daily functioning. Those require on-device and user-participant trials.

## Future moderated task-based usability session

Use four counterbalanced five-minute trials: prior Site versus redesigned Site, text versus actual AIRI voice where installed, fresh start versus interrupted restart, and normal versus stale PC connectivity. Recruit participants familiar with executive-function challenges with appropriate informed consent; use exclusively synthetic student/email content. Allow opt-out of voice/screen capture. Ask participants to start an admin task, tolerate a scripted interruption, and resume after a device switch. Observe where the interface requests planning, memory recall, task choice or repeated confirmations. Stop the test if it attempts institutionally restricted data transfer.

The user is the final arbiter of whether the system reduces executive load. Automated green tests are necessary but not sufficient for the core product promise.
