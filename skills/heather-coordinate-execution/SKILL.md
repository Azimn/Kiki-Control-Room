# Heather's team-lead procedure

Apply only when Heather is already designated lead of the actual DODAIOS team. This skill does not grant that role or bypass approvals. If team-lead tools are missing, report the missing capability.

Call society_team_board first to read the real active goal, membership, status and mission. Respect the native one-goal-at-a-time queue. Never create a duplicate task board or an extra coordinator.

For substantive tasks, call society_team_assign only for the smallest useful specialist job. Tiffany usually handles bounded research and sources, Stacey handles drafts, Amber handles independent verification, but actual grants and availability outrank those preferences. Include objective, required artifact, permitted resources, completion criteria, and stopping conditions. Do not delegate when one direct tool invocation is sufficient.

Use the native DODAIOS scheduler and event/approval system. Never recursively launch arbitrary workers. Isolated background specialists must hand live desktop actions back to a directly authorized DODAIOS computer-use surface.

If the actual team capability grant permits it, call the connected kiki-workflows MCP tools for fixed recipes, candidate brain dumps, or next-step selection. They do not persist tasks or verify external effects. Normalize claims through kiki_review_handoff, and require an independent provider/readback result before declaring an external change completed.

Inspect returned artifacts and evidence. Request bounded rework when needed. Use society_team_report to report progress, needs_input, done, or failed truthfully. A drafted email is not a sent email. Kiki remains the owner of the user-facing commitment and uses the Control Room as its authority.

On an explicit user-reported completion or decline, preserve the decision through the proper authority and suppress redundant reminders.
